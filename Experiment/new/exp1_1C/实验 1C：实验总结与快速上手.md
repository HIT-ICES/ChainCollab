# 实验 1C：BPMN→DSL 源目标行为一致性验证实验总结

## 1. 实验目标

实验 1C 用于验证 BPMN 源模型经 `newTranslator` 转换为 DSL 后，源目标两侧在有界范围内是否保持行为一致。

本实验只关注 BPMN→DSL 的转换一致性，不验证 Fabric、Geth、Solidity 或实验三运行时行为。实验三格式的 `logical_path.json` 只作为附加格式化产物，用于让 1C 的路径结果能够以相同结构被阅读和复用，但不写入实验三目录，也不作为 1C 的核心证明结果。

核心结论由两部分组成：

- `bounded trace equivalence`：BPMN 路径集合与 DSL 路径集合双向包含。
- `step-wise transition preservation`：对应路径上的每一步迁移保持 enabled set、guard、effect、state diff 和 final state。

## 2. 实验总体流程

实验流程由 `/root/code/ChainCollab/Experiment/new/exp1_1C/scripts/run_supplychainpaper_pipeline.py` 统一串联。虽然脚本名保留了 `supplychainpaper`，但它是通用 pipeline，可以通过环境变量运行任意案例。

完整步骤如下：

1. `prepare`
   初始化案例目录，生成 `config/run_config.json` 和 `config/path_bound_config.json`。

2. `run_newtranslator`
   调用 `/root/code/ChainCollab/src/newTranslator/generator/bpmn_to_dsl.py`，将 BPMN 案例转换为 DSL 文件 `translator/dsl.b2c`。

3. `extract_bpmn_raw`
   从 BPMN XML 中抽取参与者、消息、事件、网关、业务规则任务、消息流、顺序流等原始结构。

4. `build_bpmn_semantic_graph`
   将 BPMN 侧信息映射为 UBTS/GLSTS 的 JSON 实现，输出 `semantic/bpmn.semantic_graph.json`。

5. `extract_dsl_raw`
   解析 `dsl.b2c`，抽取 DSL 中的 participants、globals、messages、gateways、events、businessrules、flows。

6. `build_dsl_semantic_graph`
   将 DSL 侧信息映射为 UBTS/GLSTS 的 JSON 实现，输出 `semantic/dsl.semantic_graph.json`。

7. `normalize_semantic_ids`
   基于 1B 的 BPMN→DSL 匹配 trace 做 ID 归一化记录，输出 canonical 语义文件。

8. `generate_bpmn_paths`
   从 BPMN UBTS 中枚举有界 traces。

9. `generate_dsl_paths`
   从 DSL UBTS 中枚举有界 traces。

10. `normalize_paths`
    对两侧路径结果做统一格式化。

11. `compare_path_sets`
    检查 BPMN traces 与 DSL traces 的双向包含，验证 bounded trace equivalence。

12. `simulate_bpmn_trace` / `simulate_dsl_trace`
    生成路径级迁移轨迹，用于步骤级比较。

13. `compare_step_traces`
    比较对应 trace 的步骤级迁移保持性。

14. `generate_logical_paths`
    将通过验证的 DSL traces 导出为与实验三 `logical_path.json` 一致的附加格式。

15. `summarize_behavior_results`
    汇总实验结果，生成 `reports/behavior_summary.json` 和 `reports/behavior_summary.md`。

## 6. 快速上手

进入仓库源码目录：

```bash
cd /root/code/ChainCollab/src
```

运行默认案例 `SupplyChainPaper`：

```bash
python3 /root/code/ChainCollab/Experiment/new/exp1_1C/scripts/run_supplychainpaper_pipeline.py
```

运行指定单 DMN 案例：

```bash
EXP1C_CASE_NAME=amazon \
EXP1C_BPMN_FILE=/root/code/ChainCollab/Experiment/BPMNwithDMNcase/amazon.bpmn \
EXP1C_DMN_FILE=/root/code/ChainCollab/Experiment/BPMNwithDMNcase/amazon.dmn \
python3 /root/code/ChainCollab/Experiment/new/exp1_1C/scripts/run_supplychainpaper_pipeline.py
```

运行多 DMN 案例：

```bash
EXP1C_CASE_NAME=customer \
EXP1C_BPMN_FILE=/root/code/ChainCollab/Experiment/BPMNwithDMNcase/customer.bpmn \
EXP1C_DMN_FILES=/root/code/ChainCollab/Experiment/BPMNwithDMNcase/customer.dmn,/root/code/ChainCollab/Experiment/BPMNwithDMNcase/customer2.dmn \
python3 /root/code/ChainCollab/Experiment/new/exp1_1C/scripts/run_supplychainpaper_pipeline.py
```

运行文件名带空格的案例时，输入路径需要加引号；如果 1B 中案例名使用下划线，1C 的 `EXP1C_CASE_NAME` 也应使用下划线：

```bash
EXP1C_CASE_NAME=Hotel_Booking \
EXP1C_BPMN_FILE='/root/code/ChainCollab/Experiment/BPMNwithDMNcase/Hotel Booking.bpmn' \
EXP1C_DMN_FILE='/root/code/ChainCollab/Experiment/BPMNwithDMNcase/Hotel Booking.dmn' \
python3 /root/code/ChainCollab/Experiment/new/exp1_1C/scripts/run_supplychainpaper_pipeline.py
```

查看单案例结果：

```bash
cat /root/code/ChainCollab/Experiment/new/exp1_1C/cases/<CASE_NAME>/reports/behavior_summary.md
```

查看路径集合比较：


## 7. 常用环境变量

| 变量 | 作用 |
| --- | --- |
| `EXP1C_CASE_NAME` | 案例名，也是 1C 输出目录名。需要和 1B trace 目录名保持一致。 |
| `EXP1C_BPMN_FILE` | BPMN 输入文件路径。 |
| `EXP1C_DMN_FILE` | 单个 DMN 输入文件路径。 |
| `EXP1C_DMN_FILES` | 多个 DMN 输入文件路径，用逗号分隔。优先级高于自动发现。 |

如果不显式传 DMN，脚本会尝试按 BPMN 文件名前缀自动发现同目录下的 `*.dmn`。对于多 DMN 案例，建议显式传 `EXP1C_DMN_FILES`。

## 8. 注意事项

- 1C 的核心证明结果是 trace 集合双向包含和步骤级迁移保持，不是 `logical_path.json`。
- `logical_path.json` 只生成在 `Experiment/new/exp1_1C/cases/<CASE_NAME>/logical_paths` 下，不影响实验三目录。
- `max_loop_unroll` 当前默认为 2，用于与实验三路径边界保持一致。
- `max_depth` 当前默认为 30，用于覆盖带一次回路展开后的较长路径。
- DMN 输出采用 decision table rows 的有界枚举策略。
- 消息 payload 只有在后续 guard 需要对应业务变量时，才会进入路径分支枚举，避免普通 payload 字段造成无意义路径膨胀。
